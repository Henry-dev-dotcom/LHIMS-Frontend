# Clinician workflow usability simulation — 13 October 2026

## Summary

A repeatable, synthetic Playwright walkthrough compared the clinician workspace immediately before and after the consultation simplification commit. For the common **document a visit, preserve the draft, and return to the queue** task at a 390 × 844 mobile viewport, the updated flow required **one fewer click**, had **49.1% less measured vertical scroll travel**, and produced a **10.1% lower modeled task time**.

These are **simulation results, not observed clinician-study outcomes**. No clinicians participated; all patient data and API responses were synthetic.

## Setup and task

- **Before:** `d4c8340` (`fix: improve department messaging accessibility and document API`)
- **After:** `06585c5` (`Simplify clinician consultation workflow`)
- **View:** Chromium, 390 × 844 CSS pixels, mobile emulation.
- **Repetitions:** Five independent browser sessions per version, same fixture and task.
- **Task:** Open the waiting patient’s visit, enter the same short note, ensure the draft is saved, and return to the clinician queue.
- **Data safety:** All API calls were intercepted and answered with a static synthetic clinician, encounter, note history, and draft-write response. No real patient data or backend was used.

## Results

| Measure | Before | After | Change |
|---|---:|---:|---:|
| Mean interaction clicks | 4.0 | 3.0 | **−1 click (−25%)** |
| Mean vertical scroll travel | 2,734 px | 1,392 px | **−1,342 px (−49.1%)** |
| Modeled task time | 31.07 s | 27.94 s | **−3.13 s (−10.1%)** |
| Mean browser-run elapsed time | 355 ms | 272 ms | −84 ms (automated harness time only) |
| Latest draft reached the mocked API | 5/5 runs | 5/5 runs | No loss observed |

The before flow explicitly clicked **Save Draft** before returning to the queue. The after flow returned to the queue, where the existing save-on-leave behavior flushed the latest draft. The click count includes opening the visit, focusing the note editor, saving/returning actions, and navigation as encountered by the browser. Scroll travel is cumulative vertical document scroll movement generated by the scripted interaction.

### Modeled-time assumptions

The modeled estimate uses the same fixed assumptions for both versions: **0.9 seconds per click**, **45 words per minute** for composing the identical note, **1 second per 600 px** of vertical scroll, and **0.25 seconds** of common synthetic persistence overhead. This estimate is useful for comparing the interaction shapes, not predicting real clinical throughput. Browser elapsed time is reported separately and is strongly influenced by the fast mocked server and test harness.

## Secondary check: finding prior notes

A separate short walkthrough also checked the tradeoff introduced by collapsing note history. Before the change, the latest prior note was rendered inline; after the change, it was behind a disclosure. In that task, the UI required **3 clicks in both versions** (the after version trades the removed Save Draft click for the disclosure click). Scroll travel was **1,367 px before and 1,351 px after** (about **1.2% less** in this single exploratory run), while total document height decreased from **3,265 px to 2,488 px**. The history panel is shorter by default, but this simulation does **not** show a material scroll reduction for users who specifically need to read the prior note; opening the disclosure adds an action.

That is an important usability tradeoff: history review is less visually dominant for routine visits, but not itself a reduced-click path. Consider a future compact “latest note preview” in the collapsed summary if clinicians commonly need to scan the newest prior note without opening the full history.

## Interpretation and limits

- The strongest simulated gain is for **drafting and leaving safely**, which avoids a redundant manual-save click and removes substantial vertical movement in the test flow.
- The note-history disclosure improves default page compactness, not the number of steps to inspect a note.
- This was one representative note-entry journey on a phone-sized viewport. It did not measure diagnostic ordering, prescriptions, disposition, specialist forms, interruption recovery, or clinician error rate.
- Playwright actions are faster and more deterministic than human actions; the modeled time is assumption-based. The wall-clock browser time is not an estimate of a clinician’s task duration.
- Results should be validated with several clinicians using de-identified scenarios before making claims about real-world productivity or changing clinical workflow.

## Follow-up recommendation

Run a moderated, task-based study with clinicians on mobile and desktop. Measure completion time, clicks, scroll distance, draft persistence, missed safety information, and perceived workload. Include both a routine visit (no history review) and a returning patient (history review), and retain all existing clinical safeguards and completion requirements.
